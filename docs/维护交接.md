# 悬壶维护交接

## 1.55 版本记录

本次应用版本为 **1.55**。本版补充了急性肾损伤病例的出院留观规则。透析结束后，如果患者的自身尿量仍略低，但循环、代谢与肌酐均符合病例要求，可在连续观察 30 个模拟分钟后正常出院。短时药物利尿不计入自身尿量，肾功能恶化仍需复评。

## 版本号与合并

- 发布编号由维护者确定，日常修正沿用当前编号及位数。在同一版本中补充功能，更新该版本的说明；发布新版本时，将新记录加在历史记录之前。
- 页面版本来自 `prototype/game.js` 的 `APP_VERSION`，游戏内公告来自同文件的 `RELEASES` 首条。构建脚本会校验两处编号完全一致。存档、病例生成和会诊码的兼容版本各自独立，仅随对应格式或行为的迁移更新。
- 核对合并内容时，对比上游主分支与待合入分支的文件差异，包括 README 引用的文档。遇到双方已经发布的版本编号冲突，向维护者确认下一版编号。PR 标题和说明注明实际游戏版本，便于对应线上反馈。

## 网页同步与发布核对

1. 游戏逻辑和界面的源文件位于 `prototype/`。用 `python tools/build_site.py --sync-web` 更新仓库内的 `web/`，再用 `python tools/build_site.py --check-web` 核对副本。
2. 用 `npm test` 验证病例与引擎。出院规则改动同时验证可以出院和应当继续留观的病例。浏览器验证方式见 [README 的构建与发布说明](../README.md#构建与发布)。
3. 用 `python tools/build_site.py` 构建网站和离线版。发布时对照游戏内「关于」、下载页和 `dist/部署包/version.json` 的版本号；托管站点可以直接读取 `/version.json` 核实线上产物。
