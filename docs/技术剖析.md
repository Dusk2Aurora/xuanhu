# 悬壶 · 技术剖析

> 这份文档把项目里**可迁移到其他模拟/游戏/系统的做法**抽出来，配上真实代码片段。
> 不讲"怎么玩"，只讲"怎么建出来的、踩过哪些坑"。

---

## 一、核心思想：机制驱动，而不是规则驱动

大多数"模拟类"游戏是**规则驱动**的：

```
if (给了胰岛素) 血钾 -= 1.2
if (输生理盐水) 血压 += 10
```

这种写法的死穴：**同一个操作在不同病情下结果一样**。补液对失血性休克和对肺水肿都是"血压+10"，
玩家永远学不到"为什么"。

这个项目走的是**机制驱动**：

```
病理模块只写"负荷/驱动"（比如出血速率、气道阻力、分流比例）
引擎每帧根据负荷推导生命体征（血压 = 心输出量 × 外周阻力）
```

好处：**操作的正确性由机制自然决定**，不用为每个操作×每个病情组合写特例。

### 具体做法

`S.mod` / `S.svrDrive` / `S.shuntSrc` 这类变量是**模块写给引擎的输入**，
`S.map` / `S.spo2` / `S.hr` 是**引擎算出来的输出**。

```js
// 模块只写驱动
S.svrDrive = Math.min(16, (S.svrDrive || 8) + 0.012 * dtMin);

// 引擎统一推导
const toneTarget = clamp(17.5 * baro * (0.45 + 0.55 * reserve) * pressorGain
    - (S.infection || 0) * 11.0
    + (S.svrDrive || 0)
    + clamp(((S.icp || 0) - 0.60) * 45, 0, 18)   // Cushing 反应
    + (tm.svr || 0), 4, 42);
S.svr = lerp(S.svr, toneTarget, clamp(0.45 * dtMin, 0, 1));
```

> **教训 1**：早期模块直接写 `S.svr = ...`，被引擎每帧覆盖，导致"子痫前期怎么治都不好"。
> 后来改成只写 `svrDrive` 才通。**分层边界要一次定死，否则会反复踩。**

## 二、生理引擎怎么搭

### 2.1 状态变量分层

| 层 | 例子 | 谁写 |
|---|---|---|
| **负荷层**（输入） | `bleedRate`、`shuntSrc`、`svrDrive`、`infection`、`toxinLoad` | 病理模块 |
| **状态层**（积分量） | `vol`（容量）、`k`（血钾）、`hb`、`lungWater`、`coHb` | 引擎积分 |
| **输出层**（推导量） | `map`、`spo2`、`do2`、`ph`、`uo` | 引擎每帧算 |

只在"状态层"做积分，输出层永远不存历史——这样读数和状态不会打架。

### 2.2 血流动力学

```js
const co = S.hr * S.sv / 1000;          // L/min = 心率 × 每搏量 / 1000
S.do2 = co * S.hb * (1 - (S.coHb || 0)) * S.sao2 * 1.34;   // 氧输送

function bp(S) {
  const map = computeMap(S);            // MAP = CO × SVR + 右房压
  const pp = clamp(34 * (S.sv / 70) * (17 / Math.max(8, S.svr)), 15, 62);  // 脉压
  return { sys: map + pp * 2 / 3, dia: map - pp / 3 };
}
```

要点：

- **脉压由每搏量与外周阻力共同决定**——不是拍脑袋给的收缩压/舒张压差
- **DO2 里含一氧化碳血红蛋白**：CO 中毒时血氧读数正常但携氧不足，这个"陷阱"是机制自然产生的

### 2.3 氧合：分流方程 + Hill 曲线

```js
const hill = p => {
  const x = Math.pow(Math.max(1, p), HILL_N);
  return x / (x + Math.pow(HILL_P50, HILL_N));   // Hill 饱和曲线，P50 ≈ 26.6
};

// 分流方程：SaO₂ = (1−Qs/Qt)·Hill(PaO₂) + Qs/Qt·SvO₂
const svo2Prev = clamp(1 - (S.vo2 || 250) / Math.max(80, S.do2 || 900), 0.15, 0.85);
S.sao2 = clamp((1 - S.shunt) * hill(S.pao2) + S.shunt * svo2Prev, 0.15, 1);
```

最精妙的一点：**SvO₂ 不是常数，由 Fick 方程推**（`SvO₂ = 1 − VO₂/DO₂`）。
于是"同一个分流，循环越差血氧越低"——这是真实现象，也是免费得到的。

### 2.4 肺泡通气与 PaCO₂

```js
const va = Math.max(0.35, S.vt * (1 - vdvtEff) * S.rr / 1000);   // L/min
const paco2T = clamp(0.863 * S.vco2 / va, 10, 135);              // 肺泡通气方程
S.paco2 = lerp(S.paco2, paco2T, clamp(0.5 * dtMin, 0, 1));

const PAO2 = (S.fio2 == null ? 0.21 : S.fio2) * 713 - S.paco2 / 0.8;
const aaGrad = 5 + 40 * S.shunt + 25 * Math.max(0, vdvtEff - 0.33);   // A-a 梯度
S.pao2 = lerp(S.pao2, clamp(PAO2 - aaGrad, 25, 640), clamp(0.5 * dtMin, 0, 1));
```

> **教训 2**：`lerp` 是让"读数平滑逼近目标"的关键。直接赋值会让数字瞬间跳变，
> 玩家会觉得"假的"。用 `lerp(x, target, rate*dt)` 就有生理惯性。

### 2.5 酸碱：用微分方程而不是覆盖

```js
const hco3Gen = clamp(0.004 * (24 - S.hco3) / 8 + 0.004, 0.0015, 0.020) + (S.hco3Boost || 0);
const hco3Cons = ... ;   // 由乳酸、酮体等消耗
S.hco3 = clamp(S.hco3 + (hco3Gen - hco3Cons) * dtMin, 1, 40);
```

> **教训 3**：早期每帧 `S.hco3 = hco3Base`（覆盖），导致任何改变都被立刻抹平。
> 改成"生成 − 消耗"的积分后，代偿才有过程感。

### 2.6 数值稳定性的四件套

```js
const clamp = (v, a, b) => Math.min(b, Math.max(a, v));
const lerp = (a, b, t) => a + (b - a) * t;

// 1) 所有输出都 clamp 到生理可能区间
S.spo2 = clamp(S.sao2 * 100, 35, 100);   // 低于 35% 与生命不相容

// 2) 积分步长上限，防止快进时爆炸
const dt = Math.min(60, dtSec / 60);

// 3) 微分用"每步变化率 × dt"，不要用"每步固定量"
S.k += kProd * dtMin - kExcr * dtMin;

// 4) 关键区间加"防发散"上限
S._vfRisk = (S._vfRisk || 0) + dtMin * (S.k - 7.35) * 2.2;   // 累积风险
if (S._vfRisk > 1.15) triggerVf(S);
```

> **教训 4**：有个 bug 是"每帧往 `tempDrive` 累加"，不衰减 → 体温跑到 59℃。
> 阵发性症状要用**设置**（`= 0.055`），不要用**累加**（`+= 0.055`）。

## 三、药代动力学：一阶动力学 + 平台效应

```js
// 给药时记录：起效时刻、持续时间、效应向量、剂量缩放
S.pk.push({ id, n, t: S.t, onset, dur, eff: s.eff, scale });

// 每帧按一阶动力学算浓度
const c = Math.exp(-Math.LN2 * (S.t - p.t) / (p.dur * 60));   // 半衰期衰减

// 效应 = 方向 × 幅度 × 浓度 × 剂量缩放 × 饱和度
const cMod = c / (1 + c * 0.6);   // 饱和：浓度再高也不会无限放大
```

三个设计点：

1. **起效延迟**（`onset`）：给胰岛素不会瞬间降钾
2. **饱和平台**（`c/(1+0.6c)`）：防止大剂量产生离谱效应
3. **相互作用走浓度**：两种药同时存在时，用**累积暴露量**算协同，而不是一次性加值

```js
// 相互作用：饱和累积，避免"药代谢完了副作用还在"
S._ixAcc = S._ixAcc || {};
const acc = S._ixAcc[idx] || 0;
S._ixAcc[idx] = Math.min(1, acc + dtMin / 240);            // 4 小时饱和
const ixStrength = S._ixAcc[idx];
```

## 四、病理模块的接口设计

每个病例是一个对象，只实现四个方法：

```js
{
  id: 'highK', name: '高钾血症',
  init:   { vol: 4.25, k: 6.8, hr: 131, sv: 44, svr: 13.5, ... },
  drivers:{ kProd: 0.011 },                 // 持续负荷
  complaint: '突发心悸、乏力 6 小时…',       // 主诉
  goal:   ['血钾 < 5.5', '心律稳定'],        // 目标
  check:  S => [...没达标的原因],            // 出院判据
  hint:   '…',                              // 上级医师提示
  advance(S, dtMin) {                       // 每帧推进
    S.k += S.drivers.kProd * dtMin;
  },
}
```

这个接口的好处：**新增一个病例 = 写一个对象**，不用改引擎。

> **设计经验**：病例之间可以叠加（`nMods`），因为每个模块只改自己的载荷，
> 引擎统一结算——组合爆炸的问题被架构消化了。

## 五、测试方法论（这部分最值得抄）

这个项目有 10 个测试脚本，最有价值的是两个：

### 5.1 单调性测试

对**同一个操作**，验证"更多 → 更有效"：

```js
// 给 1 L vs 2 L 液体，血压必须有差距且方向正确
const a = run('bleed', S => give(S, 'nacl', 500), 20);
const b = run('bleed', S => give(S, 'nacl', 1000), 20);
assert(b.map > a.map, '剂量-效应方向错误');
```

### 5.2 配对差分测试（机制测试）

**同一个操作，在不同病理下必须有不同后果**——这是"机制驱动"的试金石：

```js
function diff(mod, setup, minutes) {
  const ctrl = run(mod, null, minutes);      // 不给药
  const test = run(mod, setup, minutes);     // 给药
  return Object.fromEntries(KEYS.map(k => [k, test[k] - ctrl[k]]));
}

// 同样 1500 mL 晶体液：
const ed = diff('edema', S => give(S, 'nacl', 1500), 22);   // 肺水肿：SpO₂ 必须↓
const bl = diff('bleed', S => give(S, 'nacl', 1500), 40);   // 失血：MAP 必须↑
assert(ed.spo2 <= -2, '补液没有加重肺水肿');
assert(bl.map >= 5, '补液没有改善失血性休克');
```

这套测试抓到过 **35 条机制断言**，也抓到过"补液对肺水肿反而改善"这种模型错误。

### 5.3 内容回归

每个病例跑两遍：**规范治疗** vs **放任不管**，要求前者出院、后者死亡或恶化。

> 这保证了"游戏是可通关的，且摆烂会死人"——两个方向都不能错。

### 5.4 数值审计

```js
const LIMITS = { temp: [30, 43.5], hr: [20, 220], k: [1.8, 9.5], ... };
// 扫描全部病例 × 全部时间点，超过人体可能范围就报错
```

抓到过：哮喘 SpO₂ 掉到 24%、SVR 冲到 60、体温 59℃。

## 六、踩过的坑（最有价值的部分）

| # | 坑 | 现象 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | **覆盖式写入** | 子痫前期怎么治都不好 | 模块写 `S.svr`，引擎每帧覆盖 | 改用 `svrDrive` 驱动 |
| 2 | **累加不衰减** | 体温 59℃ | `tempDrive += 0.055` 每帧 | 改成 `= 0.055`（设置） |
| 3 | **地板效应** | 补液对肺水肿"没区别" | 40 分钟时两组都跌到血氧地板 | 缩短观察窗口到 22 分钟 |
| 4 | **单位混杂** | 钾曲线不动 | 图表共用一个 y 轴，钾被钠压平 | 双纵轴 |
| 5 | **固定病例** | 每次都是同一个病人 | 病例里写死 age/sex | 创建时重新随机 |
| 6 | **引用不存在的功能** | 提示让"交叉配血" | 文案与实现脱节 | 加提示可达性审计 |
| 7 | **路由被吞** | 泼尼松写了却查不到 | `ROUTE_MAP` 里 `prednisone: null` | 删掉该行 |
| 8 | **构建产物没更新** | 改了代码 APK 没变 | 忘了 `cap copy` | 构建脚本固化步骤 |

**共同点**：都不是"算法错"，而是**架构边界不清**或**流程漏了一步**。

## 七、工程组织

```
prototype/
  engine.js      1512 行  生理引擎（无依赖，浏览器/Node 双跑）
  generator.js    910 行  33 个病理模块 + 随机病例生成
  substances.js   628 行  215 种物质、88 条别名、42 对相互作用
  game.js        2435 行  UI、交互、状态管理
  diagnosis.js    805 行  诊断推理
  handbook.js     544 行  病例档案
  mentor.js       483 行  上级医师规则
  signs.js        459 行  体征解读
  ... 共 16 个模块，约 9700 行
```

几条原则：

- **引擎零依赖**：可以单独 `require()` 跑回归测试，不开浏览器
- **UMD 包装**：同一份代码跑在浏览器 `<script>` 和 Node 里
- **无框架**：原生 DOM，打包成单文件 508 KB，离线可用
- **数据与逻辑分离**：药物、病例都是数据表，改内容不用碰代码

## 八、如果想复用这套思路

**适合**：任何"有内在规律、玩家要理解规律"的模拟——医疗、化工、金融、生态、电路。

**不适合**：规则简单的休闲游戏（机制驱动是过度设计）。

**最小可行结构**：

```
state.js     —— 状态变量与积分
derive.js    —— 从状态推导"玩家看到的数字"
modules/     —— 每个场景只写负载
tests/       —— 配对差分 + 单调性
```

**关键三条**：

1. 输入与输出分层，模块永远不写输出
2. 所有演化用"速率 × dt"，不用"每帧固定量"
3. 用**配对差分**测机制，用**单调性**测剂量效应
